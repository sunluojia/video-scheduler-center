# 代理方案

**调度中心维护一个通用代理池。给每个代理打上用途（比如爬取程序的“获取信息”“下载视频”），再给每个用途设置怎么走：直连，还是用代理池里的代理，用哪个文件夹的，先用哪条。个别设备可以单独设置，还能走这台设备的本机端口。** 爬取程序每做一次任务前，按任务的用途向调度中心要一条线路，用完归还并报告这条线路的表现。调度中心据此控制每条线路同时使用的数量，自动避开出问题的线路，过一阵再试探它是否恢复。

同一个代理可以同时用于几个用途，好坏按用途分开记：一个 IP 下载视频时被视频服务器限流，不影响它继续用来获取信息。

下载本身怎么做、失败后怎么重试，见[单视频下载方案](video-download-design.md)。

本文用到的几个词：

| 词 | 意思 |
| --- | --- |
| 设备 | 一个爬取程序实例。集群里可以有多台设备。 |
| 代理 | 代理池里的一条配置，包括协议、地址、端口、账号和密码。 |
| 用途 | 代理拿来做什么，按“服务 · 任务”区分，比如“爬取程序 · 下载视频”。 |
| 出口 | 网站实际看到的 IP，由测试得出。 |
| 线路 | 在一个用途下，一个出口算一条线路。几个代理共用一个出口时算同一条线路。直连和本机端口，各算设备自己的一条线路。 |

## 1. 代理池

代理池只放远程代理。本机端口不进代理池，在设备例外里填，见 2.3。

### 1.1 添加和识别

- **添加方式**：单条手填、批量粘贴，或导入 `.txt` / `.csv`（每行一条）。粘贴和导入先逐行预览，标出两类问题行：
  - 无法识别的行；
  - 重复行，即协议、主机、端口、用户名都与已有代理相同。

  确认后入库并自动测试。添加和导入时可以选放进哪个文件夹（默认是左侧正在看的文件夹）和用途（可多选）。
- **格式**：支持 `主机:端口`、`主机:端口:用户名:密码`、`用户名:密码@主机:端口` 和标准代理 URL `协议://用户名:密码@主机:端口`。
  - IPv6 主机要加方括号，例如 `[2001:db8::1]:1080`。
  - 密码含 `:` 时，第三个冒号之后都算密码；含 `@` 时，按最后一个 `@` 拆分。
- **协议识别**：没写协议的代理记为“自动”。首次测试时依次尝试 SOCKS5 和 HTTP 握手，按成功的协议写回。旧版出现过把 SOCKS5 端口当作 HTTP 使用、结果全部失败的情况。

### 1.2 用途

每个代理可以打多个用途，没打用途的代理只测试、不分配。

| 用途 | 标签 | 说明 |
| --- | --- | --- |
| 爬取程序（全部任务） | `crawler` | 爬取程序的所有任务都能用，以后新增的任务也算 |
| 爬取程序 · 获取信息 | `crawler.crawl_creator` | 抓达人主页和作品列表 |
| 爬取程序 · 下载视频 | `crawler.download_video` | 下载单个视频 |

选了整个服务，就不用再单独选它的任务。以后其他模块要用代理，在代码里加一个用途即可，代理池、页面和分配方式都不用改。

### 1.3 文件夹

- **树形**：代理池按文件夹整理，文件夹可以嵌套。每个代理放在一个文件夹里，也可以不放（显示在“未分组”）。
- **操作**：新建、改名（同一层不能重名）、删除。删除只删文件夹本身，里面的代理和子文件夹移到上一级，以它为范围的设置改为上一级。
- **换文件夹**：编辑代理时改；勾选一批后“移动到”；或者直接把代理拖到左侧的文件夹上，勾选了多个时一起移动。
- **调整顺序**：文件夹拖到另一个文件夹中间是放进去，拖到上下边缘是排到它前面或后面。用途按“优先级”分配时，就按这个先后顺序，见 2.2。

### 1.4 代理类型

| 类型 | 说明 |
| --- | --- |
| HTTP / HTTPS | HTTPS 指到代理本身也走 TLS。访问网站一律用 `CONNECT` 建隧道。 |
| SOCKS5 | 域名交给代理解析（即 `socks5h`），不依赖本机 DNS，CDN 也会按出口所在地分配节点。 |
| SSH | 每台设备各自在本机为 SSH 代理开一个 SOCKS5 隧道，断开后自动重连。认证用用户名加密码，或用私钥。首次连接记下主机指纹，存到调度中心；之后指纹变化，按认证失败处理。 |

- **IPv4 / IPv6**：指测得的出口地址版本，以实测为准，不看配置。旧版出现过设置了“只解析 IPv4”、出口却仍是 IPv6 的情况。
- **静态 / 动态**：静态代理的出口固定。动态代理可以填写刷新地址，但只能手动刷新，因为刷新会换掉这个代理上所有任务的出口。刷新分三步：
  1. 排空：不再分配这个代理，等用着它的任务都结束。
  2. 交给一台在线设备，调用刷新地址。
  3. 重新测试，页面显示新旧出口。

### 1.5 测试和测速

有两种检查，都由调度中心交给在线的设备执行，访问代理的请求从设备的网络发出，与实际使用时一致。没有在线设备时不能测。

| | 测试（可用性） | 测速 |
| --- | --- | --- |
| 什么时候做 | 新添加、改过地址或凭据、连不上后到期复测、页面上点“测试” | 只在页面上勾选后点“测速” |
| 做什么 | 经代理请求 IP 回显地址 | 经代理完整下载一个 10 MB 的测速文件：先单路下载一次，再 4 路同时下载 |
| 记录什么 | 能不能用、协议、出口 IP、IP 版本、延迟 | 单路速度、4 路合计速度（Mbps），或没下完整的原因 |
| 结果影响 | 决定代理状态，见 1.6 | 只记录、不改状态，因为测速地址自己也可能拒绝请求 |

- **测试**：批量测试时分摊到各台设备。Worker 领走测试后 3 分钟内没写回结果（比如中途退出），别的 Worker 会重新领。测试期间改过地址、协议或凭据，迟到的旧结果不算，按新配置重测，通过后才分配。
- **测什么**：经代理请求 IP 回显地址，记录出口 IP、IP 版本、延迟和测试时间。
  - 回显地址可配置，默认用 `https://api64.ipify.org`，它能返回 IPv6。
  - 连接超时 10 秒，总超时 15 秒。
- **怎么判**：只有连不上代理、握手失败或认证失败，才判这个代理不通。握手成功之后访问回显地址失败，只记录、不判坏，因为回显服务自己也可能出问题。
- **测速**：
  - 测速地址可配置，默认用 Cloudflare 测速页的下载接口 `https://speed.cloudflare.com/__down?bytes=10000000`，换成别的固定大小文件也行。
  - 速度按“下载的总字节数 ÷ 从发起到全部下完的时间”算，包括建连接的时间，与实际下载的感受一致。单路速度看一个视频下得多快；4 路合计看这条线路同时下几个视频还撑不撑得住，据此调“每条线路同时使用”。
  - 只认完整的 `200`，收到的字节数要和测速文件的大小一致（默认 10,000,000 字节，换测速地址时一起改 `SC_PROXY_SPEED_SIZE`）。`206` 部分内容、空正文、网页和截断都算没下完整，显示原因。
  - 每台设备一次只测一个代理，几个代理同时测会互相抢设备的带宽，测不准。一个代理大约 10–30 秒，慢的代理最多等 5 分钟。
  - Cloudflare 的测速页从 100 KB 到 250 MB 分几档，每档测多次，下载速度取第 90 百分位，还测上传、延迟、抖动和丢包，见[测速原理](https://blog.cloudflare.com/how-does-cloudflares-speed-test-really-work/)和[开源测速引擎](https://github.com/cloudflare/speedtest)。这里只看代理下载视频够不够快，用一档 10 MB、单路和 4 路各测一次就够了，想更稳可以多测几次比较。
- **目标网站**：能否访问目标网站以实际任务为准，不另发测试请求。列表显示整个集群最近一小时的成功数和失败数。

### 1.6 状态

代理本身有一个状态，所有用途共用：

| 状态 | 进入条件 | 恢复 |
| --- | --- | --- |
| 待测试 | 新添加，或改过地址、凭据 | 测试之后 |
| 可用 | 测试通过 | — |
| 连不上 | 测试或使用时连不上代理 | 自动隔一阵复测，间隔逐次翻倍 |
| 认证失败 | `407`、SOCKS5 认证被拒、SSH 认证失败或主机指纹变化 | 更新凭据后自动复测，或手动测试通过 |
| 刷新出口 | 动态代理正在排空或刷新 | 刷新并重新测试之后 |
| 已停用 | 手动停用 | 手动启用 |

代理所在的线路在每个用途上另有状态：正常、冷却中、限流、试探中，见第 4 节。页面上代理表的“用途”一列，每个用途一个标签，色点就是它在这个用途上的线路状态。

停用、删除、修改凭据、改用途都只影响之后分配的线路，正在进行的任务照常完成。
代理换地址、凭据或开始刷新出口后，旧租约仍可归还和记录表现，旧连接的失败不会取消新配置的测试或刷新。

### 1.7 列表和批量操作

- **搜索和筛选**：左侧文件夹树选范围（选中文件夹时包括它的子文件夹）；按主机、备注、出口 IP 搜索；按用途、状态、协议、启停、IP 版本、静态或动态筛选；在页面顶部点一条线路，筛出这条线路上的代理。
- **批量操作**：勾选后可以测试、测速、刷新出口、启用、停用、加上或去掉用途、移动到文件夹、删除。
- **列表内容**：每行显示名称、协议、地址、所在文件夹、出口 IP 及版本、用途及各用途的线路状态、状态（含原因）、延迟和测速结果（单路 / 4 路合计 Mbps，悬停看换算成 MB/s 和测速时间）、集群内的当前使用数，以及最近一小时的结果。

### 1.8 凭据

- **存放**：凭据存在调度中心数据库里。
- **页面**：页面接口只返回用户名的首尾字符和“已设置密码”。编辑时密码留空表示不改。
- **下发**：只在分配线路和测试时以明文发给设备，设备只放在内存里，不写盘。
- **不外露**：日志、错误信息和导出都不含凭据。

## 2. 每个用途怎么走

每个用途各有一份设置：先有一份集群设置，所有设备默认使用；个别设备可以设例外。没设置过的用途是直连。

### 2.1 为什么按用途分开

获取信息访问的是网站的页面和接口，下载视频访问的是视频服务器（CDN），两边的限流和封禁各算各的。同一个 IP 可能下载被限流、访问却没问题。所以：

- 一个代理用于哪些用途，由它的用途标签决定；
- 线路的并发、错误分、冷却和试探，都按用途分开记；
- 只有代理本身的问题（连不上、认证失败）对所有用途生效。

主流做法也是这样：Bright Data 的 Proxy Manager 封禁一个 IP 时可以只针对某个域名，这个 IP 访问其他网站照常使用。

### 2.2 集群设置

| 项目 | 说明 |
| --- | --- |
| 怎么走 | **直连**使用设备自己的网络出口。**代理池**可用整个池，也可同时勾选多个分组和单个代理。每个分组包含它的子分组。所选代理需要有对应的用途标签、已启用且测试通过。 |
| 调度方式 | **优先级**按数值从小到大，同级沿用代理池的文件夹和添加顺序。上一级线路满了、冷却或限流时使用仍可用的下一级。**权重**在有空位的选项中按权重抽取，分组的权重由归给该分组的空闲出口均分。两个选项都可用时，权重 3 和 1 的期望占比是 75% 和 25%。整个代理池在权重模式下按出口等权分配。已有轮询规则继续生效。 |
| 每条线路的并发上限 | 默认 2。走代理池时，同一用途的线路并发由所有爬取设备共享。相同 IPv4 出口或 IPv6 /64 网段算同一条线路。直连和本机端口按设备各算。单台机器实际能跑多少任务也受「执行程序」里的采集和下载并发限制。 |

单选代理采用自身的优先级或权重，单选子分组采用子分组的配置。相同出口只算一条线路。已选对象被删除后失去对应候选，明确选定的范围为空时任务继续等待。

### 2.3 设备例外

每台设备在每个用途上默认“跟随集群”，也可以单独设置：

- **跟随集群**：默认。
- **直连**。
- **代理池**：可勾选几个分组或代理。调度方式和每条线路的并发上限沿用集群设置。
- **本机端口**：填一个端口号，例如 `10808`，指这台设备自己机器上的代理端口，常见的是本机 VPN 客户端开的端口。
  - 协议自动识别。
  - 设备在容器里运行时，本机地址由部署配置给出，例如 `host.docker.internal`。
  - 这条线路只属于这台设备。换节点由本机的代理客户端负责，调度中心只管它通不通。
  - 页面显示最近一次测到的出口，可以手动重新测试。

其他说明：

- 一台设备在一个用途上只选一种来源，本机端口不与池里的代理混用。
- 设备按实例标识识别。设备离线后例外保留，重新上线继续生效。
- 设了例外的设备如果用了池里的代理，仍然和其他设备共用这些线路的并发上限和好坏判断。
- 设置修改后，对之后分配的线路生效，进行中的任务不受影响。

## 3. 线路怎么分配

1. **申请**：设备每次做任务前申请一条线路，带上用途、设备标识、任务，以及这个任务已经失败过的线路。
2. **挑选**：调度中心按这台设备在这个用途上生效的设置挑选：
   1. 只看打了这个用途、在选定文件夹范围内的代理。
   2. 去掉不能用的代理：已停用、连不上、认证失败、刷新中、出口未知。
   3. 把出口相同的代理合并成一条线路，线路内取排在最前的代理。
   4. 去掉这个用途上在冷却的线路、已经占满的线路，以及这个任务失败过的线路；如果失败过的线路去掉之后一条不剩，就允许重用。
   5. 按配置的优先级、权重或已有轮询规则选出一条。
3. **答复**：返回代理地址、凭据和出口。设置是直连或本机端口时，直接告诉设备直连或走哪个端口。
4. **没有可给的**：告诉设备过多少秒再来，以及原因：线路都占满了、都在冷却，或者没有可用线路。
5. **归还**：任务结束时归还线路，并报告这条线路的表现。
6. **没归还的**：设备每 15 秒的心跳会带上它正在用的线路，60 秒没有心跳就收回。设备宕机后名额自动释放。已经过期的租约，迟到的心跳也续不上，因为名额可能已经给了别的设备。
7. **不超发**：线路的使用情况存在调度中心数据库里，分配时加行锁，多个进程同时分配也不会超出并发上限。

IPv4 出口按地址区分；IPv6 出口按 `/64` 网段合并，因为 CDN 通常按 `/64` 识别 IPv6 用户。出口未知的代理要先测试，通过后才参与分配。

## 4. 线路好坏怎么判

设备归还线路时报告五种表现之一。下载视频时哪种失败对应哪种表现，见单视频下载方案第 3 节。

| 表现 | 调度中心怎么处理 |
| --- | --- |
| 正常 | 这条线路在这个用途上的错误分减 0.5，最低为 0。 |
| 可疑 | 错误分加 1。到 3 分，线路在这个用途上进入冷却。 |
| 代理不通 | 这个代理标为连不上，所有用途都不再分配，隔一阵自动复测（设备报告前已复测过一次）。同一出口的其他代理不受影响。 |
| 认证失败 | 这个代理标为认证失败，所有用途都不再分配，直到更新凭据后复测通过，或手动测试通过。 |
| 限流 | 线路在这个用途上限流 `Retry-After` 秒，缺省 60 秒。限流单独记，期间这条线路普通申请和提前试探都不放，之前发出的租约报正常也不提前解除。到期回到限流前的状态：原来正常的直接恢复，原来在冷却和试探循环里的照旧只放一个试探。 |

- **作品列表读取**：有 `listing_result` 的租约单独记录完整列表、空正文或读取异常。读取异常只走任务退避。获取信息线路在最近 2 分钟内有 3 个不同任务报告重复空正文，且期间没有完整列表时，暂停分配 60 秒，到期直接恢复。读取异常和空正文不会延长已有的试探冷却。
- **为什么用错误分**：一次失败说明不了问题。成功会把分数拉回去，时好时坏的代理不会被误判；连续失败的线路很快被避开。
- **冷却和试探**：
  - 冷却从 60 秒起。到期后只放一个申请去试探。
  - 试探成功：恢复使用，错误分清零。
  - 试探失败：再次冷却，时间翻倍，最长 30 分钟。
  - 冷却时间各加减 20% 的随机量，免得多条线路同时到期。
- **线路都不可用时不停摆**：调度中心从正常错误分触发的冷却线路中选最早到期的一条提前试探，最多每 60 秒一次。平台或网络恢复后，线路会自己陆续恢复。
- **直连和本机端口**：用同样的规则，只是记在这台设备自己的线路上。

需要人处理的只有这几种，都在页面上提示，见单视频下载方案第 5 节：

- 代理认证失败；
- 某个用途上某台设备没有可用的代理；
- 某个用途上某台设备的线路试探一直失败，冷却都已到最长 30 分钟；
- 没有在线的爬取程序，新添加的代理没法测试。

## 5. 实现要点

- **浏览器取地址**：Chromium 不支持带认证的 SOCKS5。遇到这类代理，设备像对 SSH 一样，在本机开一个无认证的 SOCKS5 转发，浏览器按上下文使用对应线路；下载器则直接连代理。
- **连接池**：设备为每个代理维护各自的连接池，换线路时只为当前任务新建连接。
- **识别协议**：没写协议的代理，设备先自己发 SOCKS5 问候，几秒内按 SOCKS5 回应的就是 SOCKS5，否则按 HTTP 试。不要直接交给 HTTP 库去试 SOCKS5：httpx 等库做 SOCKS5 握手时不受超时控制，遇到不回应的 HTTP 代理会一直等下去。
- **认证失败的两种样子**：经 HTTP 代理访问 http 地址时，认证失败是一个 `407` 响应；访问 https 地址时，是建立隧道失败、错误里带 `407`。两种都按认证失败报告。
- **调度中心保存的数据**：代理（含文件夹和用途）、文件夹、各用途的集群设置和设备例外、各用途的线路使用情况和状态，以及最近 24 小时的线路表现（用于统计），过期的定期清理。调度中心重启后状态照旧。
- **传输日志**：设备每次传输记一条，内容包括用途、代理、出口、失败的步骤、HTTP 状态和耗时，不记凭据和完整地址。

## 6. 接口和页面

调度中心的页面接口（不鉴权）：

| 接口 | 用途 |

| `PATCH /api/proxies/{proxy_id}` | 修改代理，包括文件夹和用途。凭据和刷新地址不回显，没提交就不改；地址或凭据改过会重新测试 |
| `POST /api/proxies/parse` | 识别粘贴或导入的文本，逐行返回解析结果和问题，不返回密码 |

| `POST /api/proxies/move` | 把一批代理移到某个文件夹，或移出文件夹 |
| `POST /api/proxies/uses` | 给一批代理加上或去掉用途 |

| `GET /api/proxy-alerts` | 需要人处理的问题，见第 4 节末尾 |

## 7. 验收

- **导入识别**：能识别四种格式、IPv6、含冒号的密码和重复行；没写协议的 SOCKS5 代理，测试后写回 SOCKS5。导入时选的文件夹和用途都生效。
- **用途**：
  - 没打用途的代理不分配；只打了“下载视频”的代理不会分给获取信息。
  - 打了“爬取程序（全部任务）”的代理，获取信息和下载视频都能用。
  - 同一个代理用于两个用途时，下载视频这边的线路冷却，获取信息照常使用这条线路。
- **文件夹**：文件夹可以嵌套、拖动排序；删除文件夹后，里面的代理和子文件夹到了上一级。优先级相同时，排在前面的文件夹先用。
- **设置**：
  - 没设置过的用途直连。
  - 没有设例外的设备用集群设置。
  - 例外只用某个文件夹的设备，只分到那个文件夹里的代理。
  - 配了本机端口的设备只走自己的端口。
  - 清除例外后，设备回到集群设置。
- **集群并发**：两台设备在同一个用途上落到同一条线路时，合计不超过设定值。一台设备宕机后，60 秒内名额被收回。
- **共用出口**：两个代理共用一个出口时算一条线路，重试时不会换到同一出口的另一个代理。
- **错误分**：
  - 一条线路偶尔失败一次，不会被冷却。
  - 连续 3 次可疑就进入冷却，其他设备在这个用途上也不再分到它。
  - 试探成功后恢复。
- **代理不通和认证失败**：代理不通时所有用途都停用它，复测通过后恢复；`407` 标为认证失败，更新凭据后自动恢复。回显服务不可用时，代理不被判坏。
- **限流**：收到 `429` 后，这条线路在这个用途上限流，其他线路继续。限流期内这条线路一个申请都不放，试探租约报限流也一样；到期后原来在冷却循环里的线路只放一个试探。
- **迟到的心跳**：租约过期、名额给了别的设备后，原设备的心跳续不上旧租约，线路上的使用数不超过上限。
- **测试结果对得上配置**：测试期间改了地址，旧结果回来后代理仍是“待测试”，新地址测试通过后才分配。Worker 中途退出，领走的测试到期后重新测。同一批里有一条回显不是 IP，只有这一条记为没测出出口并安排复测，其他照常入库。
- **线路都不可用**：下载暂停、不消耗视频的尝试次数；线路恢复后自动继续。
- **本机端口**：某台设备上的端口关闭，只有这台设备暂停，其他设备不受影响；端口恢复后自动继续。
- **动态刷新**：排空之后才调用刷新地址，进行中的任务不被打断。
- **测速**：勾选测试通过的代理点“测速”，页面先显示“测速中…”，完成后显示单路和 4 路合计速度；没测试通过的代理不测速。测速地址拒绝请求或没下完整时显示原因，代理状态不变。两台设备在线时，两个代理同时各测各的；同一台设备上一个测完才测下一个。
